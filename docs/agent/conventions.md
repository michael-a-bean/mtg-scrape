# Conventions

## Language choice (hard preference)

- **Data engineering → Python.** Ingest, ETL, scraping, Parquet writing,
  S3 operations, scheduling. Stack: pyarrow, boto3, ijson, requests.
- **Analysis → R + tidyverse + tidymodels.** EDA, feature recipes,
  modeling, resampling. Wrapped in Quarto `.qmd`.
- **Cross-language escape hatch.** Use the best tool for the job
  regardless of language. DuckDB is the canonical shared tool — reads
  Parquet from either side. Polars is fine if benchmarks justify.
- **Do not scaffold analysis as plain `.R` scripts.** Always Quarto.
- **Do not scaffold engineering as R scripts.** Always Python.

## Graphics (hard preference)

- **ggplot2 only.** Use `theme_mtg()` from `R/theme.R`.
- **Tufte principles**: maximize data-ink ratio, strip chrome, prefer
  direct labels over legends, use small multiples (`facet_wrap`) for
  comparisons.
- **Color palette**: `mtg_palette` (WUBRG + colorless + gold) for
  MTG-specific categoricals; otherwise `viridis` family for ordinal.
- **Y-only major gridlines in faint grey** — set in `theme_mtg()`.
  Don't override unless you have a reason.

## Quarto conventions

- Every analysis is a `.qmd` under `analysis/`, named `NN_topic.qmd`
  (two-digit prefix for ordering).
- Source `R/theme.R` in a `#| include: false` setup chunk via
  `here::here()`.
- Use `#| cache: true` for expensive chunks so renders stay fast.
- Captions on every figure (`fig.cap = "..."`).
- Embed external data path only through env vars (`MTG_S3_BUCKET`,
  `AWS_REGION`) — do not hardcode.

## Python style

- **Python 3.12+**; use modern features (`from __future__ import
  annotations`, `|` unions, `dict`/`list` built-in generics).
- **Streaming over buffering.** AllPrices is multi-GB decompressed —
  never `.read().json()` it; use `ijson` / chunked reads.
- **Logging, not print.** `logging.getLogger(__name__)`.
- **No `try: except: pass`.** If you catch, handle.
- **No comments that narrate the code.** Only comments that explain
  *why*, especially non-obvious constraints.
- **Module-level `log = logging.getLogger(...)` and a
  `logging.basicConfig(...)` in the `__main__` of each script.**

## R style

- **Tidyverse idioms.** Pipe (`|>`), `dplyr` verbs, `ggplot2` for plots.
- **`here::here()`** for paths — never hardcode absolute paths.
- **`suppressPackageStartupMessages({library(...)})`** in setup chunks.
- **`collect()` late.** Let `arrow` push down filters; only materialize
  when you need to plot or join to a small in-memory table.

## Commit messages

- Conventional-style prefix: `feat:`, `fix:`, `refactor:`, `docs:`,
  `chore:`.
- Imperative body. Short first line; bullets for multi-part changes.
- No emojis. No "Generated by ..." footers unless the user requests.

## S3 / storage conventions

- **Partitioning.** Always `dt=YYYY-MM-DD` at the first level after the
  data-type prefix (`prices/`, `raw/`, `dimension/`).
- **One file per partition** after compaction. Writers may temporarily
  produce multi-file partitions; compactor collapses.
- **Parquet compression.** `zstd` for new writes. Don't mix.
- **Raw bytes retained.** Keep the original `.xz` / `.json` under `raw/`
  for reprocessing. Don't delete on transform success.

## Memory / state

- **Meta-json idempotency.** Every ingest reads MTGJSON `Meta.json`
  first; if `state/mtgjson/<file>/<version>-<date>.json` already exists,
  skip. Don't bypass unless `--force`.

## What to NOT do

- Don't add frameworks or abstractions without a concrete repeated use
  case. No Pydantic, no dataclass hierarchies, no DI containers.
- Don't add a database. S3 Parquet + DuckDB covers the use case.
- Don't add orchestration (Airflow, Prefect, Dagster). GitHub Actions
  is sufficient.
- Don't add a web UI. Quarto renders to HTML; that's enough.
